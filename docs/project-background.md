# AgentKernel 项目背景说明

## 1. 项目背景

实习阶段我用 Claude Agent SDK 搭了一个配置化的 Agent 工作台（AI Agent Workbench），学会了「用框架」搭平台：Web 对话、Agent 配置化、CLI/MCP 工具接入、人工确认、审计日志。

但框架把 Agent 的核心能力都封装好了——主循环、工具调用、上下文管理、失败处理，我「会用」却「讲不清底层」。面试官如果问「ReAct 循环怎么实现、工具调用返回非法 JSON 怎么办、上下文太长为什么忘事」，只用过框架的人只能答「框架帮我做了」。

因此，个人项目反过来做：**不用任何框架，从零写一个 Agent 内核**，把「会用」补成「会造」，形成「会用 → 会造」的完整简历主线。

### 1.1 互补关系一览

| 维度 | AI Agent Workbench（实习，会用） | AgentKernel（个人项目，会造） |
|------|-------------------------------|------------------------------|
| 核心问题 | 用 Claude Agent SDK 快速交付团队工作台 | 讲清 Agent 主循环 / 工具调用 / 上下文管理底层 |
| 主循环 | SDK 内置 | 手写 ReAct 循环 |
| 工具接入 | SDK tool_use + MCP server | 手写注册表 + JSON Schema 校验 + 自实现 MCP client |
| 失败处理 | 依赖框架 | 坏 JSON 三层修复 + 允许清单 + 工具错误回灌 |
| 上下文 | 框架管理 | truncate + compact 自己实现 |
| 演示形态 | Web 平台（配置化 + 审批 + 审计） | CLI 内核（可解释、可走读） |

## 2. 项目一句话介绍

AgentKernel 是一个用 Python 从零实现的 Agent 内核，不依赖 LangChain / Claude SDK，自带知识库 MCP 工具（server 端用官方 SDK、client 端自实现），通过 CLI 演示多轮对话、工具调用和带来源的知识库问答。

## 3. 为什么从零实现，不套框架

1. **学习目的**：自建 ReAct 才能把「意图分析 → 工具选择 → 失败重试 → 上下文管理」讲清楚；用框架只能答「框架帮我做了」。
2. **定制能力**：框架把主循环封装死了，想改工具调用失败处理、加自己的记忆策略，都得绕开框架抽象；自己写，每个环节都可控。
3. **面试故事**：实习「会用」框架搭平台，个人项目「会造」内核，一条线串起来讲。

## 4. 目标与业务场景

个人项目没有「业务用户」，它的「用户」是面试官。核心场景是证明原理级工程能力，典型演示：

1. 多轮对话  
用户连续追问，第 10 轮还记得第 1 轮的要求（上下文不丢）。

2. 工具调用  
用户问「现在几点」「帮我算 123*456」，Agent 调内置工具回答。

3. 知识库问答  
用户问「XX 是什么」，Agent 走 MCP 调知识库，回答带来源引用。

4. 抗造  
故意让模型输出非法 JSON，Agent 能修复或降级为纯文本，不崩溃。

## 5. 项目故事（面试逻辑）

面试或复盘时按以下逻辑讲述：

1. **问题是什么**  
Agent 应用开发不能只会套框架。框架封装的 ReAct、工具调用、上下文管理，是 Agent 岗面试的核心考点，只会用框架答不清原理。

2. **我做了什么**  
我用 Python 从零实现了一个 Agent 内核，不依赖任何框架：ReAct 主循环、工具注册与参数校验、非法 JSON 三层修复、SQLite 记忆，并自建知识库 MCP 工具。

3. **技术上怎么做**  
内核是「思考 → 行动 → 观察 → 回复」的 ReAct 循环；工具调用走固定 JSON 协议 + JSON Schema 校验；模型输出非法 JSON 走三层修复（正则提取 → JSON 修复 → 降级纯文本）；对话历史存 SQLite，送入模型前做截断/压缩；MCP 工具 server 端用官方 SDK、client 端自实现 `tools/list` + `tools/call`。

4. **结果是什么**  
系统能演示「多轮对话 → 调工具 → 知识库带来源 → 坏 JSON 不崩」的完整闭环。相比直接用框架，它证明了我理解每个环节的原理。

5. **还缺什么**  
当前是学习型原型，不是生产系统。真实上线还需要接入生产模型网关、更完整的评估体系、健壮的错误恢复，以及针对具体业务的工具生态。

## 6. 项目定位

本项目定位为个人学习 + 求职用的可演示原型。

应该做到：

1. 主流程能跑通（CLI 多轮 + 工具 + 知识库）。
2. 架构边界清楚（8 个模块职责分明）。
3. 错误处理可靠（坏 JSON 不崩、工具报错回灌）。
4. 面试故事完整（原理讲得清）。
5. 参考 OpenClaw 源码，理解工业级 Agent 的设计取舍。

不应该做到：

1. 做成完整商业化 Agent 平台。
2. 接 IM 渠道（飞书等），CLI 演示足够。
3. 追求多租户、插件市场、企业级运维。
4. 实现复杂 RAG 优化（混合检索/重排，口头能讲即可）。
5. 重新实现 LangGraph 级别的 Agent Runtime。
