AgentKernel
个人项目总纲与面试蓝图

ReAct 内核 MCP 协议 RAG 实验

项目定位：参考 agent-study 复现最小 Agent Runtime，自己实现关键机制；先复现基线，再针对模型输出不稳定、上下文超限、知识库更新不可靠等问题做改进验证。与实习项目 AI Agent Workbench 形成「会用 → 会学习底层」的互补主线。

硬边界：不做 Workbench 的第二份实现。Workbench 负责用户、业务和治理；AgentKernel 负责学习、改进和验证框架底层机制。

历史快照（2026-09）：本页测试数、文件路径和简历表述为当时状态，不代表当前口径；当前材料见 README.md 与 docs/status.md。

1项目背景与定位

1.1 问题是什么

实习阶段用 Claude Agent SDK 搭了配置化 Agent 工作台（AI Agent Workbench），学会了「用框架」搭平台：Web 对话、Agent 配置化、CLI/MCP 工具接入、人工确认、审计日志。

但框架把 Agent Runtime 的核心机制都封装好了——主循环、工具调用、上下文管理、失败处理，我「会用」，但对底层机制的理解不够。面试官如果问「ReAct 循环怎么实现、工具调用返回非法 JSON 怎么办、上下文太长为什么忘事」，只用过框架的人只能答「框架帮我做了」。

1.2 我做了什么

个人项目不是再做一个业务平台，而是为学习底层：

  • 参考 agent-study 的简化实现，自己复现最小 Agent Runtime 基线；
  • 再针对模型输出不稳定、上下文超限和文档更新不可靠等问题做改进验证；
  • 把实习中的「会用」补成「会学习、会实现、会优化、会验证」，形成「会用 → 会学习底层」的互补主线。

1.3 研究路线：先复现，再优化

  1. 复现基线：参考 agent-study 的 Agent 教学设计，实现 ReAct、工具注册、观察回灌和持久化记忆。
  2. 工程参考：参考 OpenClaw 对工具调用修复、允许清单和载荷边界的处理思路，不复制其实现，提炼为 Python 版本。
  3. 问题驱动优化：围绕「模型输出不稳定」和「知识库更新不稳定」两个问题，增加分层降级、工具安全边界、checksum 增量更新、MySQL ngram 基线和可选向量回退。
  4. 验证方式：通过 fake LLM、故障输入、文档重复/修改和 MCP 子进程场景验证改进是否有效。
  5. 面试故事：实习「会用」框架交付应用，个人项目先复现原理、再针对问题优化，一条线串起来讲。

1.4 一句话介绍

AgentKernel 是一个用 Python 自己实现（参考 agent-study 复现）的 Agent Runtime 研究原型，不依赖 LangChain / Claude SDK。它通过 CLI、测试和评估脚本验证 ReAct、Tool Calling、上下文管理和 MCP 协议，并用一个检索样例验证文档增量索引、混合检索和来源保留。

3.1 数据库决策

SQLite 适合实习项目早期快速验证，但无法充分体现服务端场景中的连接池、并发访问、事务边界、索引设计和数据库迁移。因此 AgentKernel 将 MySQL 8 设为主存储，SQLite 仅保留为测试适配器。

MySQL 负责会话、消息、工具日志、文档元数据和文档 Chunk；Chroma 只负责可选向量索引，MySQL 保存文档与 Chunk 的事实数据。中文词法检索使用 MySQL InnoDB FULLTEXT 的 ngram parser。

数据库访问必须通过 Store/Repository 接口，Runtime 不直接依赖具体数据库驱动。这样既能在测试中使用 SQLite，也能在实际运行中使用 MySQL，而不会把数据库切换逻辑扩散到 Agent 主循环。

4.3 借鉴来源

  • 分层（runtime/ / tools/ / memory/ / utils/ / tests/）：借鉴 AI Agent Workbench 的工程组织方式，但不复制其 Web、业务和审批层。
  • 工具调用契约（tools/contracts.py）：借鉴 OpenClaw tool-call-repair 的 contracts.ts。
  • JSON 修复分层（提取 → 修复 → 降级）：借鉴 OpenClaw 的 grammar/payload/promote/stream-normalizer 分层思想。
  • 工具名允许清单 + payload 字节上限：借鉴 OpenClaw scanPlainTextToolCall 的 matcher 与 maxPayloadBytes。
  • MySQL 8 + Alembic + Docker Compose：服务端持久化与本地可复现环境。

5工具调用协议边界

5.1 协议格式

模型被要求按固定 JSON 输出工具调用：

{"action": "工具名", "action_input": {"参数": "值"}}

多工具调用：

{"actions": [
  {"action": "工具名1", "action_input": {...}},
  {"action": "工具名2", "action_input": {...}}
]}

最终回答：

{"action": "final_answer", "action_input": "回答内容"}

5.2 边界规则

  1. 工具必须通过 registry 注册，模型不能调用未注册的工具。
  2. 模型输出先按协议契约分类；工具调用必须命中名字允许清单（单工具与多工具数组都查），未注册工具一律降级为纯文本。
  3. 工具参数必须经 JSON Schema 校验（required / type / properties / enum / items / additionalProperties），非法参数返回明确错误。
  4. 模型输出非法 JSON 走三层修复：正则提取 → JSON 修复 → 降级纯文本；单候选 payload 超过 256KB 直接放弃修复。
  5. ReAct 循环设 MAX_STEPS 上限，防止死循环；多工具调用当前按顺序执行。
  6. 历史超预算时 truncate 固定首条用户要求；超过 compact 阈值时优先摘要压缩，压缩失败降级截断。

6安全边界

6.1 已实现的 Runtime 级防护

  1. SQL 使用参数绑定；计算器使用 AST 白名单，不使用 eval/exec。
  2. 工具名称使用 allowlist，参数执行基础 JSON Schema 校验。
  3. MCP 帧具备长度限制。
  4. Agent 具备最大步数，JSON payload 具备大小限制。
  5. API Key 从环境变量读取，知识库 MCP 示例只暴露查询和列出操作。

6.2 当前未实现边界（面试必须说明）

  1. 文档和 MCP 返回内容属于不可信数据，尚未实现完整 Prompt Injection 防护和工具结果隔离。
  2. 外部 --mcp 命令默认依赖用户信任，尚未实现命令白名单、环境变量隔离和操作系统沙箱。
  3. 文档入库尚未完整限制允许根目录、文件数量、PDF 大小和递归深度。
  4. 尚未实现用户认证、授权、工具风险分级、人工审批、多租户隔离和限流。
  5. 工具日志仅用于 Runtime 观察，尚未实现敏感字段脱敏、访问控制、加密和不可篡改审计。
  6. 尚未实现完整资源保护，包括计算器数值规模、Schema 深度、动作数量和所有检索参数上限。
  7. StdioMCPClient 的读取操作暂无超时控制，恶意或卡死的 MCP server 可能阻塞调用。

6.3 如果扩展为联网服务

优先补充：输入与资源限制、外部 MCP 沙箱、工具授权/审批、Prompt Injection 防护、日志脱敏和认证授权。当前项目不把这些企业治理能力伪装成已完成能力。

7实现范围

7.1 必须实现并可验证

  1. runtime/agent.py 能执行最多 MAX_STEPS 的 ReAct 循环。
  2. tools/contracts.py 能区分单工具、多工具和最终回答协议。
  3. tools/registry.py 能注册工具、生成描述、校验参数并把异常转为观察结果。
  4. tools/json_repair.py 能处理带噪声/代码围栏/尾逗号/单引号 JSON，失败时降级纯文本。
  5. ContextConfig 能执行首条用户要求保留、最近消息截断和摘要压缩降级。
  6. mcp/framing.py、mcp/client.py、mcp/server.py 能完成 initialize → tools/list → tools/call。
  7. eval.py 和 tests/ 能用 fake LLM 验证上述行为，不依赖真实 API。

7.2 检索实验能力

  1. memory/：通过统一 Store/Repository 接口完成 MySQL 消息恢复和工具观察记录，SQLite 仅用于测试。
  2. rag/ingest.py：文档 checksum、增量更新、稳定 chunk ID、MySQL ngram 全文检索和可选向量索引。
  3. rag/ingest.py：保留 source/page/section 元数据，检索结果可生成可审计引用。
  4. mcp/server.py：通过 knowledge_query / knowledge_list 暴露只读检索能力。
  5. __main__.py：CLI 作为运维/开发入口，支持持久化知识库目录。

7.3 可降级实现

  1. 上下文压缩（compact）可以先用纯截断（truncate）替代。
  2. 向量依赖不可用时降级为 MySQL ngram 全文检索，不能降级为丢失数据的内存索引。
  3. PDF 依赖不可用时只拒绝 PDF，不影响已有 MD/TXT 索引和查询。
  4. MCP server 可使用纯 Python stdio 实现，不要求官方 SDK。
  5. 2 分钟录屏可省，测试、评估和索引一致性验证优先。

7.4 默认不做

  1. 不做 Web、SSE、Agent manifest、子 Agent 和业务路由。
  2. 不做人工审批、企业鉴权、跨会话产品记忆和完整审计平台。
  3. 不做 IM 渠道（飞书等）和真实企业系统接入。
  4. 不做文档管理 UI、企业权限平台和多租户知识库。
  5. 不做 Agent 插件市场、多租户和生产级部署。
  6. 不引入 LangChain / Claude SDK 作为 Runtime 实现。

2026-08-29 ~ 2026-09-08 ✅ 已实现

M1 · ReAct 内核可跑

阶段目标：完成最小可用内核，打通「CLI 输入 → ReAct 循环 → 调工具 → 输出回复」的主链路。不追求知识库/MCP，重点是确认 ReAct 循环能稳定跑通、工具能调、坏输入不崩。

数据流

用户输入 → runtime/agent.py 组装上下文（system prompt + 工具描述 + 历史 + 输入）
        → runtime/llm.py 调 DeepSeek，返回 {"action": "...", "action_input": {...}}
        → 解析：工具调用 or final_answer？
           ├─ 工具调用 → registry 执行 → 观察结果写回历史 → 回到循环
           └─ final_answer → 输出给用户 → 结束

关键点

  1. MAX_STEPS 上限，防模型反复调工具死循环。
  2. 工具执行结果（观察）回灌历史，让模型「看到」结果再决定下一步。
  3. 工具报错 → 错误信息作为观察回灌，让模型重试，不崩。

交付物

  1. 可运行的 CLI Agent（多轮 + 工具 + 抗造）。
  2. runtime/llm.py / runtime/agent.py / tools/contracts.py / tools/registry.py / tools/json_repair.py / memory/sqlite_store.py。
  3. 2 个内置工具：get_current_time、calculator。
  4. .env.example 和本地启动说明。

验收标准

  1. CLI 能多轮对话，不崩。
  2. 能调 2 个内置工具（问「现在几点」「算 123*456」）。
  3. 故意让模型输出带废话/残缺的 JSON，能修复或降级，不崩。
  4. 重启后接着上一轮对话，还记得上下文。
  5. 工具报错（如计算器除 0）不崩，错误回灌让模型重试。

M2 · MCP 协议与示例工具链打通

阶段目标：在 M1 内核基础上，完成一条用于验证外部状态接入的检索实验链路：文档解析 → 指纹增量入库 → 词法/向量召回 → 来源引用 → 通过 MCP 暴露给内核。

数据流

Agent → mcp/client.py（自实现 tools/list + tools/call）
     → mcp/server.py（官方 SDK 可选，注册 knowledge_query / knowledge_list）
     → rag/ingest.py（PDF/MD/TXT → 分块 → MySQL ngram + 可选向量混合检索）
     → 检索返回带来源片段

关键点

  1. server 端用官方 mcp SDK，不重复造轮子；client 端自实现，证明懂协议底层。
  2. 检索结果必须带来源（文档名 + 片段），这是「带来源」的关键。
  3. MCP 工具注册进内核 registry，内核当作普通工具调用，无感知。

交付物

  1. 知识库入库 + 检索能力。
  2. MCP server（官方 SDK 可选适配/纯 Python stdio）+ MCP client（自实现）。
  3. 打通「Agent → MCP → 知识库」链路。
  4. 至少 1 个测试文档。

验收标准

  1. PDF/MD/TXT 文档能加载并建立持久化索引（PDF 依赖 PyMuPDF）。
  2. knowledge_query 能检索出相关片段并带来源。
  3. Agent 通过 MCP 调知识库，回答带来源。
  4. 5 个评估用例全过，或至少核心用例过。
