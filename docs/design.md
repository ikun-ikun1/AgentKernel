# 技术文档：设计决策

> 记录「为什么这么做」——每个决策背后都是面试能讲的一段话。
> 配套：[architecture.md](architecture.md)（架构）。

---

## 一、为什么从零写，不套框架

- **学习目的**：自建 ReAct 才能把「意图分析 → 工具选择 → 失败重试 → 上下文管理」讲清楚；用框架只能答「框架帮我做了」。
- **定制能力**：框架把主循环封装死了，想改失败处理、加记忆策略都得绕开抽象；自己写每个环节都可控。
- **面试故事**：实习「会用」框架搭平台，个人项目「会造」内核——形成「会用 → 会造」的完整叙事。

---

## 二、非法 JSON 三层修复（核心设计）

> 参考 OpenClaw `tool-call-repair` 的思路：**把「模型会犯错」当默认前提**，而不是假设它永远输出正确。

| 层 | 做法 | 应对的问题 |
|----|------|-----------|
| 1 正则提取 | 从整段文本里用正则抠出 `{...}` | 模型在 JSON 前后夹了废话 |
| 2 JSON 修复 | 补括号、去尾注、修引号/逗号 | JSON 结构不完整/格式错 |
| 3 降级纯文本 | 三次都失败 → 把原始输出当普通回复 | 彻底救不回来 |

**设计要点**：
- 分层隔离：每层职责单一，失败才落到下一层。
- 降级是底线：宁可答得差，不能崩。

## 三、上下文管理取舍（truncate vs compact）

- **truncate（截断）**：砍最老的，简单、快，但丢信息。
- **compact（压缩）**：旧对话总结成摘要，保留关键信息，但多一次 LLM 调用、有成本。
- **本项目策略**：SQLite 存完整历史；送入模型前先截断到窗口内；特别长时先压缩再截断。

> 面试点：「对话忘事」不是模型傻，是上下文窗口有限的工程取舍。

---

## 四、MCP 两端都写

- **server 端**（官方 SDK）：证明会「用标准协议」注册工具、声明 schema、返回结果。
- **client 端**（自实现）：证明懂协议底层——`initialize` → `tools/list` → `tools/call` 全流程。
- **价值**：面试问「MCP 你理解到什么程度」，能答「两端都写过，理解 tool 生命周期全流程」。

## 五、技术选型理由

| 选型 | 理由 |
|------|------|
| DeepSeek（OpenAI 兼容） | 便宜、接口标准，换模型只改 base_url |
| ChromaDB | 本地、轻量、Python 原生，个人项目够用 |
| bge-small-zh-v1.5 | 中文效果好、体积小、本地可跑 |
| SQLite | 标准库自带、零部署，CLI 场景够用 |
| 自实现 MCP client | 证明原理，不重复造 server 轮子 |

## 六、边界（明确不做）

- ❌ IM 渠道（飞书等）：渠道工程不考 Agent 原理，CLI 够演示
- ❌ Agent 框架（LangChain/Claude SDK）：核心逻辑全手写
- ❌ 多租户 / 卡片交互：没做就不写进简历话术
- ❌ 复杂 RAG 优化（混合检索/重排）：知道思路、口头能讲即可，不实现

> 原则：话术只讲做过的事，避免被面试深挖穿帮。

## 七、面试 30 秒版本（定稿）
